# Metamorph Constitution — v0.1 (PROPOSED)

**Proposed:** 2026-10-26. **Ratification:** Pending owner review. Designed for 2 developers / hackathon; not derived from Casper's long-lived release process.

## I. Demo-value and vertical slices first

Prefer one working PHP → TS migration end to end to large speculative architecture. Timebox spikes, stop low-value refactors and keep a demonstrable runnable path. Every significant feature needs observable acceptance criteria, not an essay.

## II. Independent behavioral verification

Generated code is not accepted by model confidence or compile-only checks. Required parity gates (G0–G4), a valid baseline, negative controls, and independent candidate runtime remain authoritative. `INCONCLUSIVE` is not `PASS`. An agent cannot modify verifier criteria/fixtures to make its run green.

## III. Lean Spec Kit

One short spec + plan + task list per significant vertical slice. Small fixes can use a GitHub Issue/PR checklist without creating a new spec bundle. Clarify/checklist/analyze are optional for ordinary low-risk work; use when contracts, security or unclear behaviors warrant it. Spec outputs are planning artifacts, not a mandate to implement everything they mention.

## IV. Fast CI, quality at the right boundary

PR CI only formatting/lint, typecheck, unit/contract smoke and build, target 2–4 minutes. Full PHP/TS differential, concurrency, long model API and demo smoke run on demand before declaring product acceptance. No per-PR hash recertification, approval digest, 15-minute collector or mandatory full benchmark rerun for documentation changes. A truly failing required fast check must not be bypassed for green CI.

## V. Clear two-person ownership

Vladimir owns migration agent/orchestrator/integration; Ilia owns independent baseline runner/comparator/Oracle. Review the other's change to shared contracts before merging. Keep code in separate directories/PRs until the interface is agreed, avoid concurrent edits to one spec/branch, and require proof of executed checks in PRs.

## VI. Narrow scope and OSS provenance

One benchmark, one language pair, one controlled runner and one simple UI. External code is reused when its license allows it and attribution is preserved. Distinguish original hackathon implementation, pre-event research, borrowed open-source code and untouched upstream benchmark fixtures. No copy/paste of Casper governance machinery by default.

## VII. Secure bounded execution

Use supported Meta API access, validated inputs, environment-held secrets, isolated disposable workers, no untrusted arbitrary code execution on host. Models receive controlled contexts and write only target workspaces. Fixed budget/timeout limits; failure is recorded explicitly. Do not expose held-out data via prompts/logs.

## VIII. Evidence without ritual

Evidence is tied to run IDs, actual commands/results, scenarios, before/after state, model usage and timings. Record hashes where meaningful for reproducible research runs, not as an authorization step for every commit. Spec completion, PR merge and product-verified PASS are distinct states.

## Governance

Accepted architecture ADRs and explicitly approved requirements override autogenerated plans. Significant cross-cutting changes need a brief ADR with impact and rollback. Owners may simplify process for reversible changes; never weaken the independent Oracle's correctness requirements just to ship faster.
