# Public engine-backed fault matrix — design only

The 12 IDs and their order are exactly the `faultControls` in [linux-docker-result.json](../mmp-183/linux-docker-result.json). **Every engine-backed row is `NOT_RUN`.** All rows require both owners' authenticated exact-design-SHA approval, an independent implementation review and separate explicit authorization for the identified disposable execution window. No destructive method is authorized by this matrix.

The future executor must predeclare the specific injection point and handshakes and run one case at a time. "Falsifier" below is an intentionally defective **test-harness/evaluator control**, not permission to delete a sentinel or weaken the production G0 adapter. The control must be demonstrably rejected by an independent observer; a fault being detected may be a successful *test outcome*, but is not a G0 PASS. Codes below describe reachable current paths or explicitly state `UNSPECIFIED_DECISION_PENDING`; actual timing may expose more than one fault.

## Shared evidence and cleanup legend

- **E:** privately retain exact case/run/owner/VM/daemon/endpoint IDs; evaluator, worker, recipe, image and fixture hashes; monotonic trigger and completion times; upstream/daemon observations; pre/post full container, volume and network inventory; actual exit/error and separate normal/finalizer ledgers/catalogs. Keep raw inspect/stdout/stderr and paths off Git/LLM. Include the independent supervisor's continuous lease/audit/heartbeat and no-write-after-seal evidence.
- **N/F:** normal and independent ledger-finalizer outcomes are separate. A valid normal zero requires verified full inventory and `emergencyRemoved=0`; a later finalizer removal is emergency activity, not normal cleanup. If quiescence, identity or evidence is uncertain, the stricter proposed supervisor blocks both mutations and reports unknown/partial counts. Current code may attempt exact-owned cleanup after an inventory failure; do not mistake the proposal for current behavior.
- **M:** existing mocked Docker/model tests are listed below as model coverage only. Genuine daemon-backed observation and separate failure controls remain required.
- **Policy:** a missing observation is `INCONCLUSIVE` or `ERROR` as appropriate, never a manufactured zero or PASS. Any observed `G0_EVIDENCE` or `G0_CLEANUP` integrity failure has ERROR precedence in [assess()](../../packages/workshop-audit/src/g0/run.mjs#L97). If an early failure prevents creation of any public receipt, retain the incident as `ERROR` with code `UNSPECIFIED_DECISION_PENDING`; do not claim the current code always returns a DTO.

## Explicit code and mock-model mapping

- [command()](../../packages/target-worker/src/controller.mjs#L65) spawns the trusted Docker CLI with no shell, kills the **CLI process** on timeout/abort and resolves on its close; that does not prove the daemon rolled back its request. [G0Docker.call/close/finalize](../../packages/workshop-audit/src/g0/docker.mjs#L219) add promise tracking, bounded joins, a cleanup interlock and independent ledger reopening, not a shared cross-process quiescence barrier.
- [g0.test.mjs](../../packages/workshop-audit/test/g0.test.mjs#L537) models stuck promises, timeout, partial create, inventory/ownership mismatches, emergency removal and foreign same-prefix resources. [g0-run-controls.mjs](../../packages/workshop-audit/test/g0-run-controls.mjs#L180) models post-seal tamper, failing receipt writes, background capture and late settlement. None is a genuine Docker fault injection. The tests were inspected in D0, not reclassified as executions of the engine matrix.
- [safeCode()](../../packages/workshop-audit/src/g0/policy.mjs#L262) permits a closed set and maps unknown codes to `G0_INTERNAL`. Individual `G0_*` codes above are phase-dependent. `UNSPECIFIED_DECISION_PENDING` is a design placeholder, **not** a claimed existing G0 code.

## Additional high-value controls — all `NOT_RUN`

1. **Fsync/rename/receipt fault:** inject failure before and after file fsync and rename, including loss of the directory entry, partial trace, receipt write and full storage; retained incident must remain ERROR and refuse qualification. The current file write does not fsync the parent directory. Separately witness the receipt because the current catalog excludes it.
2. **Inventory/deletion race:** use predeclared barriers to change test-owned inventory between list, inspect and exact-ID action; ensure the sentinel is unchanged and the outer supervisor stops on unexplained drift. Independently falsify a stale snapshot.
3. **Daemon loss, hang and emergency recovery:** lose the guest daemon or block a command while external supervisor remains live; prove no overlapping mutation after uncertainty, evidence-preserving quarantine and later owner-controlled recovery. Recovery must never convert ERROR into PASS or emergency removal into normal zero.
4. **Positive baseline unchanged:** before the fault series, and again only if the approved plan explicitly permits a separate post-series control, run the fixed clean public qualification at the approved identities. Compare fixture IDs, pins, controls and independently verified normal/F `0/0/0`. Failure or unavailable evidence stops the series; this is not an automatic retry.

No claim here establishes private candidate G0, formal G4, complete product acceptance, or independent physical custody.
